What a machine cannot do here, and why (from the gap records):

- **a successful sign-in** (human-required, Functional): This is a sign-in form and the application has no credentials configured in QA NXT, so a valid submission cannot be made.
- **business rules between fields beyond those named** (human-required, Workflows): Rules such as "business accounts need a company number" exist in requirements, not in the page; only rules visible in names or observed in behaviour were tested.
- **an anti-forgery token** (human-required, Security): This form submits with script, so a token would travel in a header that the page does not declare.
- **the stored record** (human-required, Data integrity): QA NXT has no access to the application's database, and a stored record is only observable where the application shows it back.
- **direct navigation to a later step** (unsupported, Multi-step forms): The steps share one address, so there is no later step to open directly.
- **load, stress, spike and endurance testing** (unsupported, Performance): These need many concurrent virtual users over time. The browser worker measures single-user response times; it is not a load generator.
- **a network failure during submission** (unsupported, Error handling): This form submits by navigating, so a network failure is shown by the browser's own error page, not by the application.

## Known limitations

- **Firefox and WebKit** are not installed in this environment (the Playwright CDN is blocked),
  so their compatibility tests were generated and skipped, never passed. Status: NOT VERIFIED.
- **Load, stress, spike and endurance testing** are outside the browser worker; only single-user
  response times are measured.
- **Data integrity** needs access to what the application stored; QA NXT has none, so it is a
  human task unless the application exposes a read API.
- **Business rules** that are not visible in the page are not inferred. Cross-field rules are
  found from field names (confirm/start/end/min/max) and from probing.
- **Server-side limits** that the page does not declare (an upload size limit) are reported as
  unknown, never guessed.
- **Visual baselines** are recorded on the first run; a visual test can only fail on a later run.
- The **double-submission** check counts submissions the server did not refuse. A second click
  that sends a request the server rejects with 4xx is not counted as a duplicate.
- **Tab order** is checked through consecutive simple fields; a date, radio group or file input
  stops the chain, recorded as a partial gap.
